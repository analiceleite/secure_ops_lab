Entrada da aplicação · identidade e autorização

O caminho do usuário passa pelo gateway. O monitoramento usa conexões internas separadas, detalhadas no próximo mapa.

Monitoramento · disponibilidade, autenticação e qualidade da coleta

O Zabbix server faz as consultas e avalia as triggers. O frontend apresenta os resultados; o PostgreSQL persiste configuração, histórico e eventos. As setas indicam quem inicia cada comunicação.

Disponibilidade · a API responde?

  • GET /health a cada 20s; timeout de 5s, uma tentativa, somente HTTP 200 e sem seguir redirects.
  • Falha do cenário abre problema; nova execução válida com sucesso recupera.
  • nodata(90s) abre um problema técnico separado para ausência de resultados. A avaliação é periódica, não um cronômetro exato de 90s.
  • A verificação não atravessa o gateway e não comprova o caminho inteiro do usuário.

Autenticação · houve falhas repetidas?

  • HTTP agent a cada 30s; o coletor valida e conta LOGIN_ERROR únicos na janela móvel de 300s, sem somar amostras sucessivas.
  • Contagem válida ≥5 abre um problema; somente nova contagem válida <5 recupera. Um erro isolado não abre alerta.
  • Qualidade 0 ou ausência de amostras por 90s abre problema técnico. Falha não vira zero e não recupera autenticação.
  • É triagem agregada do client, não prova de ataque. Visitante autenticada com 403 é autorização negada, não erro de login.

Dashboard privado: disponibilidade, problemas ativos, contagem de LOGIN_ERROR e qualidade da coleta. Histórico de itens e eventos de trigger com política de 7d; retenções configuradas não comprovam expurgo observado. O token administrativo temporário foi revogado; a operação usa credenciais próprias. Com o Zabbix server parado, não há avaliação contínua nem monitor externo dele neste laboratório.

Entrega 02 concluída · limites explícitos

  • Sessão: expiração aproximada de cinco minutos e bloqueio após retirada de grupo confirmados pela autora. Sem refresh ou promessa de revogação instantânea.
  • Navegador: saúde autorizada, MFA e atributos do cookie de sessão relatados. Não houve coleta de valores de cookies.
  • OIDC: audiência/issuer/assinatura/nonce/state, grupos e cookie adulterado testados no binário real em ambiente isolado.
  • Operação: logout, OTP após retomada, Keycloak indisponível e ciclo API parada → 502 → recuperação validados.
  • Regressão: 35 testes API + 10 estáticos + 12 verificações isoladas aprovados. Não equivale a auditoria de produção.
Como explicar o fluxo em uma entrevista
  1. O navegador entra pelo gateway, não diretamente pela API.
  2. O gateway inicia Authorization Code com PKCE no Keycloak. O client exige senha e TOTP nos novos logins da aplicação.
  3. O gateway valida emissor, assinatura, audiência e nonce; casos negativos foram exercitados com tokens de teste no mesmo binário, sem alterar o emissor principal.
  4. O grupo /secureops-operators decide a autorização. A visitante pode autenticar e, mesmo assim, receber 403.
  5. Requisições autorizadas seguem para api:3000 pela rede interna. A API não valida tokens e o gateway está configurado para não encaminhá-los.
  6. Em paralelo, o Zabbix server consulta o health check por service, sem abrir uma porta da API no host. Isso permite observar a API mesmo com o Keycloak indisponível.
  7. Para autenticação, o server consulta um coletor por monitoring. O coletor lê o Keycloak por identity, com service account exclusiva, e retorna apenas agregado e qualidade.
  8. Cinco LOGIN_ERROR em cinco minutos abrem um problema. Uma falha de coleta abre outro problema técnico, nunca um zero artificial. O PostgreSQL preserva configuração, histórico e eventos do Zabbix.

Limites que fazem parte do desenho

HTTP local e start-dev são exceções aprovadas para contas fictícias; não há criptografia de transporte. A rede identity não é interna e não demonstra bloqueio de saída. Containers autorizados na rede service podem acessar a API diretamente. Host, administradores e daemon Docker pertencem à base de confiança.

Volumes não são backup. Esta implementação não é ZTNA completo nem configuração pronta para produção.
